# Inventor Add-in Troubleshooting

## Add-in is not listed or does not load

- Verify Inventor 2027 is the running host and the manifest is in a documented 2027 discovery folder.
- Validate the manifest XML, add-in type, class/client IDs, assembly path, and load flags against the local 2027 Creating an Add-in topic.
- Verify the add-in implements `ApplicationAddInServer`, its COM identity matches the manifest, and the DLL/dependencies are accessible.
- Check the Inventor Add-In Manager for load errors and inspect application logs/debug output. Do not register legacy COM state as a workaround for a malformed registry-free manifest.

## Build succeeds but load fails

- Confirm the target framework is supported by the installed 2027 host and the intended deployment. The 2027 `What's New` recommends .NET 10; older SDK wizard notes may still mention .NET 8.
- Confirm the interop DLL version and copy/local-reference settings.
- Check `UseInventorAssemblyContext`, add-in location, and dependency probing behavior. Dependencies loaded in a different context are not interchangeable merely because assembly names match.
- Launch under the debugger or attach to the actual `Inventor.exe`; report this as host-load testing, not a build test.

## Ribbon control is missing or duplicated

- Check the active ribbon/environment name and the document type.
- Ensure persistent UI creation follows `FirstTime` behavior; don't create the same panel/tab on each activation.
- Verify internal names/client ID and listen for Ribbon reset if customization must be restored.
- Re-test after unload/reload and reset; distinguish command definition from visible command control.

## COM event is not firing

- Keep the event source object and delegate/event-interface reference alive.
- Use the event interface/delegate generated by the installed 2027 interop assembly.
- Check duplicate subscription/unsubscription and source object lifetime.
- Break at the callback and inspect the actual Inventor host process; do not assume a COM event is a normal .NET event on the primary API interface.

## Flat-pattern DXF output is empty or wrong

- Verify the source is sheet metal and `HasFlatPattern` is true (or explicitly decide whether to create one).
- Verify the selected DataIO context supports the output format. Follow the Inventor 2027 DataIO guidance and sheet-metal DXF example.
- Check output path permissions, existing file state, the format string, and the requested DXF version/layers.
- Test output geometry/layers in a CAD viewer or receiving workflow and keep the original model unchanged unless specified.
- Report each skipped/failed document; never silently treat an empty output file as success.
